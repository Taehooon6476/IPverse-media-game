# game3d/ — GameSpec v1/v2 runtime (three.js)

The default engine for new games. GameSpec **v2** authors a world and ordered missions; v1 remains supported by the original SF/RPG modes. Model output stays bounded data, with no generated game code or `eval`. The runtime source is shared; each v2 game's geometry, positions, selected cast, mechanics and mission progression come from its own validated spec. Three.js 0.170.0 loads from jsDelivr through the import map in `index.html`. There is no build step. This is executable browser WebGL, not a compiled Unreal game.

| file | role |
|---|---|
| `index.html` | import map, HUD, dialogue box, win/lose overlay, ad overlay |
| `ui.css` | page and HUD styles |
| `runtime3d.js` | boot: `./spec.json` → validate → `./release.json` → pre-roll ad → mode by genre prefix. three.js loads lazily, so a CDN failure shows an error instead of a blank page |
| `gamespec3d.js` | `validateSpec` and `defaultSpec`. A copy of `game/gamespec.js` plus the optional 3D fields |
| `world.js` | renderer and post-processing, input, third-person camera, GLB/billboard actors, player controller, particles, seeded noise |
| `anim.js` | skeletal animation for UAL-rigged GLBs: clip retargeting by bone name, speed-matched locomotion blend, attack/hit/death layers, right-hand weapon attach |
| `ualclips.js` | UAL clip roles and bone names (mirrors `workers/rig/ual_clips.json` and `ual_bones.json`; no three.js, so Node tests import it) |
| `sf.js` | `sf-shooter` and `sf-survival`: neon arena, drones, projectiles, pickups |
| `rpg.js` | `rpg-explore` and `rpg-quest`: terrain, lake, village and NPC, items, monsters |
| `authored-contract.js` | strict v2 world/mission/mechanics validation; invalid v2 data never becomes a v1 arena |
| `mission.js` | pure ordered-stage progression from real collection/combat/proximity/held-interaction events |
| `authored.js` | v2 authored geometry, selected-IP actors, combat, hazards, ordered stages and start briefing |

## Authored v2 worlds

V1 had fixed `buildArena` and `buildVillage` functions, random cover/props and one objective. A prompt could change colors, templates and a small preset list, but could not author rooms, encounter positions or a multi-stage mission. V2 uses a separate execution path with these actual gameplay inputs:

1. `world.width/depth` are bounded meters; coordinates are centered signed `x/z`. `spawn` sets the real start. Up to 48 `entities` describe box, cylinder, spire, arch, tree, crystal, building, platform, beacon or hazard geometry with dimensions, rotation, tint and optional hex emissive color. Solid geometry affects player/projectile/camera collision; platforms can be landed on, and hazards hurt the player.
2. `world.propPlacements` places actual selected `props[propIndex]` GLBs or cutouts. `enemySpawns` places actual selected `enemies[enemyIndex]`, including cutout-only enemy billboards. Optional `stageId` binds each placement to its stage; otherwise the first matching stage is used. Future collection targets are not consumed before their stage. An explicit selected model/image/weapon that fails to load is an error, not a substitute IP.
3. `mission.stages` defines 1–8 ordered collect, kills, boss, reach, interact, talk or survive tasks. `entityIds`, `propIndex` and `enemyIndex` filter actual events. Counters reset at stage boundaries. `holdSec` applies to proximity holds and held E interaction; leaving or releasing resets the hold. Boss target is a count, while its actual HP is the selected enemy's HP × 8.
4. `mechanics` controls dash, jump, sprint, autoFire, regeneration, weapon damage, fire interval and interaction range. Auto-fire defaults to **false** in v2. `artDirection` directly applies sky/fog colors, fog density, exposure and bloom strength.

All IDs/indices, coordinates, quotas and supported mechanics are validated. The backend performs the stricter collision-free placement/type/lifetime checks before publishing. A requested unsupported mechanic must be rejected instead of silently presented as working. A v2 scene requires both `world` and `mission`; it cannot use the old fixed mode as a fallback.

The public `window.__ipverseGameState()` is a read-only observer returning a fresh clone of scalar/data telemetry: actor representation/IP IDs, authored entities, actual positions/HP, pending/alive enemies, collected targets and stage history. It exposes no actor, input or state mutation handle. The old localhost-only `__g3d` dev tooling remains for v1 tests; physical v2 QA does not use its teleport/state shortcuts.

## The page around a round

What a first-time player meets, in every mode (`runtime3d.js`; the words and rules are pure functions in `arpg-data.js`, so Node tests run them):

- **Loading**: every GLB and the sky's HDR load through the world's `LoadMeter` (`world.gltf`). The files the boot loads are sized ahead with HEAD requests, so the screen shows a figure that stands on a real total: `게임 불러오는 중… 62%`, a bar, the step in words and the megabytes. The figure never goes back and says 100 only at the last step; where it would stand at 99 while the world is built (the counted files all in: a game whose enemies are cutouts, 1.4–3.4 s), the step is named in its place: `게임 불러오는 중… 장면 준비 중`. The briefing's busy start button shows the same figure. A pre-roll ad plays from the start, over the loading. A version-2 game's enemies are part of that load (`AuthoredMode.loadCast`, sized ahead like the rest): their models were downloaded when each first appeared in the round, outside the figure, and at 10 Mbit/s the first enemy of a 30-second round came 10 s after the start click.
- **Briefing** (version 2): `임무 브리핑`, the stages, the start button (`임무 시작`; its name is what scripts and the broadcast's play window look for) and the keys as a list. `controlsFor(spec)` gives the keys a game really takes: no camera keys for an ARPG or a race, no dash, jump or sprint where the game has none. The same list is the line under the game and the pause card's list.
- **A device without a keyboard** (`keylessDevice`, by the primary input: a coarse pointer that cannot hover, so a phone or a tablet with a pen is one and a laptop with a touch screen is not): the briefing says `이 게임은 키보드와 마우스로 플레이해요. PC에서 열어 주세요.` over its start button, which reads `그래도 시작하기`, and the line under the game says it in place of the keys. There are no touch controls.
- **Gauges**: a game shows only the ones it uses. No health bar where nothing can hurt the hero (no enemy, no trap), no `대시` gauge without a dash or at the wheel, a crosshair only where the hero shoots. A race's HUD is the lap and gate on the left and the place, time and speed on the right, with a large 3-2-1.
- **A blow's side** (version 2): a blow reddens the picture's rim on the side it came from, a wedge toward the attacker (`AuthoredMode.hurt(damage, from)` tells the world `hurtFrom`, the vignette's shader in `world.js` takes it). Ahead is the top of the picture, behind the bottom. A blow with no side (a trap underfoot, the version-1 modes) reddens the whole rim.
- **Tips**: `AuthoredMode.tip(text, sec)` keeps a one-shot line in the notice pill for its seconds (the jump tip after the first fall, the car's keys, the ARPG's new skill, `GO!`). `hud.notice()` inside `update()` is overwritten by `refreshHud()` in the same frame.
- **Goal arrow**: the nearest place the stage has left; on a kills or boss stage the nearest enemy that counts for it once none is within 12 m (`➤ 적 72m`); on foot in a stage done by car, the car (`➤ 차 19m`). Its label keeps off the story box and the notice pill. Where the straight walk to that goal is blocked (a dungeon's rooms), the arrow leads round: it names the goal nearest on foot, points at where the way first turns out of sight (the door) and counts the walk's metres, also for what is "within 12 m" (`AuthoredMode.arrowWay`, on the walk grid, by `navNearest`: one search for all the stage's goals, twice a second, about a millisecond). In plain sight it is the straight line as before. Not for a car's road, a sky's or a platformer's climb, or a city.
- **Cut-away walls** (the ARPG's fixed camera): whatever stands between the camera and the hero fades to under half so the hero stays in sight (`world.js` `fadeOccluders`). A wall keeps a low edge under the cut (`AuthoredMode.edge`, `wallEdge`): its collider's footprint, knee-high, in the wall's own material, drawn beside the wall's group so the fade never takes it. It is what the hero is seen standing against: a crypt's dark brick at 45 % over a dark floor read as a shadow. Boxes, buildings, pillars, arch legs and the dungeon's own outer walls have one.
- **Talk**: E or Enter by the stage's person opens the dialogue, each press passes a line, and the stage counts once the last one is passed. E held down passes a line every 1.5 s (the built-in player holds E). The story box passes on E, Enter or a click.
- **Pause** (`pauseRules`, `makePause`): Esc or P open a card with `계속하기`, `다시 시작`, what `다시 시작` does from there (`다시 시작을 누르면 2단계부터 이어서 해요.`, the end card's words) and the keys, and the round's clocks stand. Leaving the window or the tab pauses too. While a round is played or paused the game hears Esc and P first and keeps them from the page around its frame (the studio's big view closes on an Esc it hears on the frame's window); with no round on (the briefing, the end card) Esc goes through to it. Under `?autoplay=1` and in a playable ad (`?playable=`) nothing pauses and no key is taken for it: a broadcast goes on, and a trial's clock is the ad page's (its keys are in the line under the game). A broadcast's play window with a person at the keys marks its game `?nopause=1`, and nothing pauses there either: a paused round sends the viewers a standing picture and holds back the round ends the ads wait for. `?noads=1` alone (the cloud stream) keeps Esc and P and drops the pause on a lost focus. A stopped round tells no end ahead (`ipverseRoundEndsIn` is null) and its capture says `일시정지`. A check that drives a game by its link in a window without the focus finds the round stopped under the card, and its next Space or Enter lands on `계속하기`: run such a check with focus emulation, as `dev/qa-modes.mjs` does, or open the game with `?nopause=1`.
- **End card**: the title, why the round ended, the result (a race's place and time; else the score, when there is one, and the time; on a loss the stage reached), the button and what it does (`2단계부터 이어서 해요`). Each mode tells its round in `endSummary(won)`; `endCard` writes the card. The round's report (`ipverse:round`) and the built-in player's restart timer come before the card's words, and a summary that throws leaves the card its own words. `다시 시작` starts the next round by itself: the card's title and the busy button show while the world is built, not the whole briefing. The card takes no key and no click on its button for its first 0.8 s (`endKey`: a person is still pressing the round's keys, Space to jump, Enter on the story box, a click to attack in an ARPG, where the button comes up near the screen's middle) and never a key held down since the round; then Enter, Space or a click. Until then the button looks as one that cannot be pressed (`ui.css` `end-wait`). Both keys are the card's own listener's, so the focused button is never pressed by them itself. The built-in player's restart and a broadcast's hold (`ipverseHoldEnd`) are not delayed, and under `?autoplay=1` a keyboard's Enter or Space does not press the card ahead of them. A playable ad's card (`?playable=`) has no `다시 시작` and takes no key: the trial is the ad page's. A round that goes on from a later stage opens with `체크포인트 · 2단계부터 다시 · 잠시 무적` and a moment of invulnerability; one that restarts the first stage is a fresh start, with neither. The built-in player's own reasons (`진행이 멈춰서 이번 판을 마쳐요.`, `자동 플레이 시간이 다 돼서 이번 판을 마쳐요.`) are the card's reason line and are 해요체 like its other lines.

- **What a round leaves**: nothing on the graphics card. A mode keeps its light probe as the render target `PMREMGenerator` gives it and disposes that (`texture.dispose()` on a render target's texture frees nothing). `disposeTree` frees, with the geometry and the materials, the shadow map of every light and the bone texture of every rigged model in the tree; `releaseDrawn` does only that, for an enemy that leaves the round before its end.

A game folder keeps the `index.html` it was made with, and a runtime hot patch brings the scripts and `ui.css` only, so the runtime makes every element it adds to the page itself (`ensure`).

`node game3d/dev/qa-round20.mjs --cdp=<port> [--only=briefing,pause,…]` plays these with real key events in a running browser and keeps its screenshots (`--out`, default `evidence/round20/G`). Its scene `bigview` plays the game inside `dev/big-view.html`, a stand-in for the studio's big view (the game in a frame, with the view's own Esc hook on the frame's window). The local fixtures (`dev/spec-*.json`) need no network; the stored games (`test/fixtures/<id>.spec.json`) read their assets from the site into `--cache`. Two measurements run only when named: `--only=weight` lists what a first visit downloads, by file, for one stored game of each kind; `--only=textures` plays five rounds of each kind under the built-in player, counts the textures three.js holds in each round and lists where the ones a past round left behind were made. Round 21's scenes are in `dev/qa-round21-scenes.mjs` and run by name: `--out=evidence/round21/G --only=wall,arrow,endkeys,firststage,botreason,smalltext,cast,climb` (the cut-away wall's edge, the arrow through the door, the end card's keys, a first-stage restart, the built-in player's reason, the small-window text sizes, the enemies' load on a 10 Mbit/s link, the built-in player's rounds on three climbing games). The checks send a key as a keyboard does: Enter and Space carry their character, so a focused button is pressed by them as in a real browser, and no key carries a native key code (the Windows code is another key on a Mac, and the page then hears a second, phantom key).

## V2 runtime verification

The local city and garden fixtures are **authored test data with existing attributed dev assets**, not AI-generated/deployed proof. Their source and screenshots are under `dev/`, which the uploader excludes. `dev/qa-authored.mjs` uses real Playwright keyboard down/up/press and pointer clicks, with only read-only telemetry queries. It completes city collection → selected enemy combat → held interaction → extraction, and garden collection → NPC talk → reach; it also checks authored collision, disabled idle auto-fire, restart and the 390px start button. Evidence is `dev/evidence/authored-runtime-verification.json` and the fully recorded WebM.

The start button stays disabled while world assets or the pre-roll ad are pending, including restart. `dev/qa-readiness.mjs` delays an actual fixture texture request and checks that early pointer/Enter inputs cannot start or disappear into an unfinished world; after the original asset response, native click and movement work. Its separate evidence is `dev/evidence/authored-readiness-verification.json`.

```bash
python3 -m http.server 8099 --bind 127.0.0.1 --directory game3d
# In a second terminal with an already installed Playwright core package:
PLAYWRIGHT_MODULE=/path/to/playwright-core node game3d/dev/qa-authored.mjs
PLAYWRIGHT_MODULE=/path/to/playwright-core node game3d/dev/qa-readiness.mjs
node --test game3d/test/*.test.mjs game/test/*.test.mjs
```

The 390px check covers layout/start visibility; physical movement QA uses keyboard/mouse on desktop. Native Unreal compile/play and AAA visual quality are not inferred from these browser checks.

## Spec fields added for 3D

These fields are optional. `server/gamespec.py` mirrors them.

- `engine`: `"phaser"` or `"three"`. Without it the game is Phaser. `make_game` writes it and defaults to `three`.
- `player.modelUrl` and `props[i].modelUrl`: a non-empty string, normally `assets/{ipId}.glb`. The server sets it for IPs that have a GLB and drops any URL the model sends. A player with a rigged GLB gets `assets/{ipId}.rig.glb`.
- `player.weaponUrl` and `player.weaponType` (`melee` or `gun`): the weapon IP's GLB (`assets/{weaponIpId}.glb`), from `player.weaponIpId`.
- `enemies[i].ipId`, `modelUrl`, `weaponUrl`, `humanoid`: an enemy IP's model (rigged when it has one and is humanoid). Entries without `modelUrl` stay procedural drones and monsters.
- `animUrl`: `assets/ual.glb`, the shared UAL clip library, copied from `runtime3d/v1/anims/ual.glb` when any model is rigged (docs/rig-contract.md).

`gamespec3d.js` is a copy, not an import of `../game/gamespec.js`, because a published game folder holds only its own runtime files. `test/gamespec3d.test.mjs` runs the 2D test cases against the copy. It also checks that both validators return identical results for 2D specs and broken variants, so a 2D rule change that is not copied fails the test.

## Deployment shape

`scripts/upload_web.py` uploads the files in the table to `runtime3d/v1/`. It skips `dev/`, `test/` and this README. `make_game` with `engine: "three"` copies them into `games/{gameId}/`. It also copies `assets/{ipId}.png` from the cutout and `assets/{ipId}.glb` from the IP's `glbAssetId` when there is one. `spec.json` and `release.json` work as in `game/`: the same ad gate, the same `광고 건너뛰기 (N)` countdown, and a missing or non-JSON `release.json` means no ad.

## Legacy v1 gameplay

The controls are the same in both families. WASD moves relative to the camera. Mouse drag or the arrow keys orbit the camera. Shift sprints, Space jumps, and Q dashes, with invulnerability while dashing. A gamepad works too: the left stick moves, the right stick looks, A jumps, B dashes, X talks, and RT fires. Every run starts with a grace period: 5 s in SF, 3 s in RPG. `prefers-reduced-motion` turns off screen shake.

- **Actors**: GLBs are normalized to 1.8 m (the player) and grounded. They face the direction of movement and get procedural bob, lean, and squash on landing. GLBs on the UAL skeleton get an `Animator` (`anim.js`) bound to the shared `animUrl` library (or their own clips). Idle, walk, run and sprint blend by ground speed. Their phase advances by distance over each clip's measured foot-planted speed, so feet do not slide. Jump, fall and land play in the air. Attacks, hit reactions and landings play on the upper body while moving and on the full body while standing. Death holds its last frame, then the body fades. Rotation tracks bind by bone name. Only the pelvis translation is kept, scaled by the rig's `ualHipsScale`. The weapon GLB goes into the right palm with a grip frame built from the hand's finger bones: blades leave the fist on the thumb side and barrels point along the fingers. Bolts spawn at the weapon's +Z tip. Other GLBs with clips play Idle and Run as before. Without a GLB, the cutout PNG becomes a billboard cropped to its opaque bounds. Without either, a procedural suited figure stands in.
- **SF**: Click or F fires toward the camera aim. A gun (or no weapon) plays the recoil clip with an aim pose. A melee weapon swings, and a three-bolt slash wave leaves the blade at the swing's impact frame. Enemies with a humanoid IP model walk on the floor (zombie walk, a zombie or sword strike that hurts on its impact frame, a hit flinch, death then fade). At most 6 are pooled across all modelled entries. Non-humanoid IP models hover like drones. Firing is also automatic whenever a drone is within the ~12° aim-assist cone, so an idle presenter still scores. On first click the pointer locks for mouse aim. Enemies are built from their `shape` (triangle dart, circle orb that strafes and shoots, square armored ram) with their `color`, `hp` and `speed`. Drones spawn after a 5 s grace, every {easy 1.6, normal 1.15, hard 0.8} s, up to {7, 10, 13} alive, and faster over time in `survive` mode. Only the nearest {easy 2, normal 3, hard 3} drones attack. A newly promoted attacker waits 2.5 s, and the rest circle at 12–16 m and hold fire. A ram bounces the drone off and it falls back for 4 s. Damage and enemy fire rate scale by {0.3/0.4, 0.5/0.5, 0.8/0.8}: base rams cost 15, 12 or 25 HP and bolts cost 10, out of 100 HP. After a hit come {1.2, 1.0, 0.6} s of i-frames, and HP regenerates {8, 5, 2}/s after 4 s without damage. On normal an idle player survives 70 s with HP never below 29 (`?test=sf-idle`). Each prop sits on a pad and respawns after 14 s. Kills drop props 20% of the time. Prop effects are `score` +100, `heal` +30 HP, `shield` 5 s, and `key` +250. The objective reads `목표: 적 N명 격파 (k/N)` or `목표: N초 생존 (k/N)`. For `sf-shooter`, a kills target above 20 plays as 20 and the HUD shows 20.
- **RPG**: The map is `map.width × map.height` tiles of 3 m each, seeded by `map.seed`. The NPC and items follow rule 2 of `game/README.md`. Standing within 2.8 m of the NPC shows the `E 대화` prompt. The dialogue pauses the world, and E, Space or Enter advances it. Monsters follow rule 3, converted at 3 m per tile. Before striking, a monster telegraphs with a red ring on the ground for 0.75 s × pace. A strike costs 1 of 3 lives, then 2 s of i-frames and a knockback. The monster that hit goes back to its spawn, or to the farthest point when the player is within 4 tiles of the spawn, and rests 2 s. Finishing the quest lights the village lanterns. A click (not a camera drag), F or RT attacks with the held weapon. A melee weapon plays `Sword_Attack` and an empty hand plays `punch`. Both hit every monster in a 120° cone within reach on the clip's impact frame. A gun plays `Pistol_Shoot` and fires a bolt. The player turns to the nearest monster in reach first. Monsters take `hp` hits. A hit makes them flinch, pushes them back and cancels a telegraphed strike. At 0 HP they play the death clip (or sink), fade out and give 10 × hp score. Killing is optional, and the objective and quest rules are unchanged. `?test=rpg-anim` stages the rigged monster next to the player and kills it.

### Every mode, under the built-in player

`?autoplay=1` (the live broadcast's demo player) plays every stage type: it walks to pickups and targets, fights, waits out a survive clock, and drives: a race round a track's road (`race.js` `raceKeys`), a city race gate to gate and a `drive` stage in the stage's car (`city.js` `botDrive`). Its watchdog (`runtime3d.js`) ends a round whose progress stands still for 40 s, so a stage it cannot play is a round that never gets further.

- The keys are its alone: under `?autoplay=1` a key from a keyboard (a trusted event) is not the hero's (`world.js` `Input.botOnly`); the built-in player's own are events the page sends. A check that must move the hero there sends its keys from the page (`dispatchEvent(new KeyboardEvent(…))`), not through the browser's input.
- It steps back out of a boss's telegraphed blow (`AuthoredMode.autoDodge`: S, facing the boss, while it winds up within two metres of its reach) and fights everything else as it did. `test/round22-boss.test.mjs` plays gm_b1188dcc0c's whole rounds (`fixtures/headless.mjs` `fightMode`, `playFight`: the enemies appear as the round asks for them, stand-ins for their models).

- `test/modes-boot.test.mjs` boots each mode (authored, city, track, version-1 sf and rpg) on a stored `spec.json` as far as Node goes: the spec validates, `boot()`'s own routing picks the module, the module's whole import graph loads and is among the files a game folder gets, the v2 modes run their first second, and every stage type of the contract has a way for the built-in player.
- It climbs (`AuthoredMode.climbToward`, `sky.js` `climbStep`): a sky world's islands and a platformer's platforms are a graph of tops, taken a step at a time with a run-up and a jump at the edge. A top that stands on the one underfoot (the first island on the start island, a platform on a platformer's floor) is stepped onto from beside it, with the jump before its side stops the hero; such a step may be as high as the hero really jumps (1.66 m in a platformer), a step across a gap keeps the contract's 1.2 m and 2.5 m. A step that is not there at the moment (a moving platform out of reach) is waited for. On a platformer's floor a goal that is down there is walked to round the walls as anywhere else. `test/round21-player.test.mjs` plays the whole rounds of three such games (`fixtures/headless.mjs` `climbMode`: the tops, the moving platforms, the coins and the props of a stored spec), and keeps the round of the sky game it always won the same frame for frame.
- `test/round18-race.test.mjs` runs whole rounds without a browser (`test/fixtures/headless.mjs`: the mode's own `update()`, the car physics, the mission director, `world.js`'s `Input`, and the built-in player's loop read out of `runtime3d.js`).
- What Node cannot run (a mode's `build()` and its drawing need three.js from the CDN and WebGL) is one page per mode in a browser: `node game3d/dev/qa-modes.mjs --chrome=<Chrome binary>` (or `--cdp=<port>` for a running one). It serves this checkout's runtime with each stored spec and that game's own assets from the site, and fails when a page shows an error, a round does not start, the built-in player gets nowhere, or the watchdog ends a round.
